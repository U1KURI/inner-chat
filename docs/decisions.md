# 決定記録（Decision Log）

要件定義の過程で出た論点と、その決定内容・理由を残す。
最新の要件は [requirements.md](./requirements.md) を参照。

## 2026-11-08 要件整理

### 出発点（依頼者の要望）
- 知人だけが入れるチャットを作りたい
- 幅の広い人たちが参加する
- 個々人が「何ができるか」を提示しておく
- ふわっとした案件が来たときに会話が始まるようにしたい
- 個々人同士のメッセージもやれるようにしたい
- 電話番号もしくはメールアドレスでアカウント作成できるようにしたい

---

### D-01 機能の範囲
- **論点**：初版で機能を「MVP / 次 / 将来」に分けて提案した
- **決定**：「あとから足す」としていた機能も全部入れる。優先度区分はなくし、実装の順番だけ持つ

### D-02 規模
- **決定**：50人未満
- **影響**：マネージドサービスの無料〜低価格枠で運用できる前提

### D-03 招待と管理者
- **決定**：招待リンクを発行できるのは管理者のみ。管理者は他のメンバーを管理者に格上げできる
- **補足（Claude 提案・採用）**：管理者を一般に戻すこともできる。ただし管理者が0人にならないよう、最後の1人は戻せない

### D-04 相談の公開範囲
- **決定**：「全体に公開」「関係者のみ」を選べる。途中から変更できる
- **補足（Claude 提案・採用）**
  - 全体 → 関係者のみ に絞るとき、すでにスレッドで発言・反応した人を候補に出し、選ばれた人は承認なしで関係者に残る（すでに会話に参加しているため）
  - 関係者のみ → 全体 に広げるときは確認ダイアログを出す
  - 公開範囲の変更・関係者を外す操作は投稿者のみ。本人はいつでも自分から抜けられる
  - 変更はスレッドにシステムメッセージで記録
  - 誰が見られるかはサーバー側（DB の行レベル権限）で制御

### D-05 お金のやり取り
- **決定**：扱わない（受発注・決済なし。「人をつなぐ」まで）
- **理由**：決済を入れると要件と法的対応が大きく増える

### D-06 提供形態
- **決定**：Web（PWA）、レスポンシブ

### D-07 Slack / LINE との差別化
- **決定**：「できること × 相談のマッチング」に独自に作る価値がある、という整理で OK
- **追加（依頼者）**：「LINE を使いたくない人も使える」ことも差別化ポイント

### D-08 管理者による「関係者のみ」相談の閲覧
- **論点**：管理者は関係者のみの相談を見られるべきか（Claude 初案：見られない、通報時のみ可）
- **決定**：「管理者の閲覧を許可する」チェックボックスを用意し、**デフォルトはオン**
- **文言**：「調整や仲裁が必要になった場合に備えて、管理者が内容を確認できるようにします」
- **補足（Claude 提案・採用）**：投稿者が後から変更可。オフでも通報された相談は管理者が見られる。状態は相談ヘッダーに表示

### D-09 関係者の追加
- **論点**：関係者を追加できるのは誰か（Claude 初案：投稿者のみ、投稿者が許可すれば関係者も）
- **決定**：投稿者だけでなく、**管理者や関係者も追加できる**。**受け取った本人の承認で加わる**。承認前に問い合わせができる
- **補足（Claude 提案・採用）**
  - 管理者が招待できるのは、管理者閲覧が許可された相談のみ
  - 問い合わせは招待に紐づく専用の会話として残る
  - 投稿者以外が招待した場合は投稿者に通知し、投稿者は承認前の招待を取り消せる
  - 招待の有効期限は14日を目安

### D-10 認証方式
- **論点**：メール認証は無料でいけるか
- **回答**：50人規模ならほぼ無料。Supabase のメール認証は無料プランに含まれ、メール送信は外部サービス（Resend 等）の無料枠で足りる。独自ドメインは年1,000〜2,000円ほど（推奨）。SMS は1通十数円前後
- **注意**：Supabase 標準のメール送信は送信数制限が厳しく本番向きではないため、外部の送信サービスにつなぐ
- **決定**：**メール認証をデフォルト**、**SMS は希望者のみ**

### D-11 AI 利用の告知
- **決定**：利用規約・投稿画面で知らせる

### D-12 承認前に見えるもの ＋ 議論マップ
- **論点**：承認前に見えるのは「タイトル・投稿者・招待者・招待メッセージ・関係者一覧」だけ、という案だった
- **決定**：「**議論の大まかな流れと、全体感における現在位置**」も見えるようにする
- **決定**：これは**全案件で AI が自動生成**する。最低限の材料が揃うまでは枠だけ用意し、「このような項目があれば、議論の流れや全体感と現在位置を出せます」と提示する
- **補足（Claude 提案・採用）**
  - 表示項目：ゴール／流れ（3〜6項目）／現在位置（①課題整理 → ②情報・選択肢集め → ③検討・比較 → ④決定 → ⑤実行・フォロー）／決まったこと／未決の論点／次の一歩／更新日時
  - 最低限の材料の目安：本文からゴールと現状が読み取れる＋投稿者以外の発言が1件以上
  - 新しい発言で自動更新（連続投稿はまとめて）、手動更新ボタンあり
  - 投稿者・関係者が手修正でき、手修正部分は自動更新で上書きしない
  - 承認前の人に見せるのは、個人名を伏せ発言を引用しない「概要版」

### D-13 「関係者のみ」相談の AI 送信（D-12 による方針変更）
- **論点**：以前は「関係者のみの相談は AI に送らない」としていたが、議論マップを全件で作るには送る必要がある
- **決定**：関係者のみの相談も議論マップ生成のため AI に送る（利用規約で明記）。ただしマッチング・おすすめには使わない。DM は送らない

### D-14 AI の提供元
- **論点**：相談先の AI は Claude になるか
- **回答**：はい。Anthropic の Claude API を推奨。API の仕事向け規約では、送った内容は標準では学習に使われない（着手時に最新規約を確認）
- **コスト目安**（相談 月100件、1件あたり議論マップ更新10回の仮定）：Claude Opus 5.5 で月数千円程度、Claude Haiku 5.5 で月数百円以下。用途で使い分けも可能。モデルの最終選択は運用者が決める

### D-15 相談ごとの AI 利用オフ
- **論点**：Claude から「相談ごとに AI を止められる設定」「承認前の人に議論マップを見せない設定」を追加候補として提示
- **決定**：**相談ごとに AI 利用をオフにできる設定を追加**。もう一方（承認前の人に議論マップを見せない設定）は不要
- **補足（Claude 提案・採用前提）**
  - 投稿時に選択、デフォルトはオン。変更できるのは投稿者のみ、途中で切り替え可
  - オフの相談は要約・タグ付け・議論マップのいずれにも AI を使わない。手動タグによるマッチングは行う
  - オフの間は議論マップ欄を手入力で埋められる
  - 途中でオフにしても生成済みのマップは残す（投稿者が削除可）。オンに戻すと生成し直す

## 2026-11-08 データ設計

### D-16 データ設計の方針
- **決定（依頼者）**：データ設計を進める
- **Claude の判断で決めたこと**（設計書 [data-model.md](./data-model.md) に反映）
  - 見られる範囲はすべて DB の行レベルセキュリティで判定する
  - 公開範囲の変更・招待・管理者操作などは DB 関数（RPC）経由に限定し、自動メッセージと通知もそこで行う
  - 招待リンクはトークン本体を保存せずハッシュだけ持つ
  - 「関係者のみ」の相談を閲覧しているだけの管理者は、発言・反応はできない
  - 全体公開の相談で議論マップを手修正できるのは、投稿者とスレッドに発言した人
  - 全体 → 関係者のみ に絞るとき承認なしで残せるのは、実際に発言・反応した人に限る
  - 関係者を外せないのは投稿者本人だけ（投稿者は抜けられない）
  - 招待の取り消しは投稿者に加えて招待者本人もできる
  - 議論マップは発言のたびではなく、最後の発言から3分ほど待ってまとめて更新する
  - 退会時はプロフィールを削除し、発言は「退会したメンバー」として残す

## 2026-11-08 招待からログインまでの実装

### D-17 登録時に招待を確認する
- **決定（依頼者）**：登録時に招待を確認する仕組みを入れる
- **方式（Claude 提案・実装）**
  - 招待リンクから連絡先を入力した時点で「この連絡先はこの招待で登録する」と予約する（1時間有効）
  - Supabase Auth の登録前フック（Before User Created）で、予約のない連絡先のユーザー作成を拒否する。アプリを通さず API を直接たたいた場合も防げる
  - 招待リンクの使用回数は、確認コードを送った時点ではなく、表示名を入れてメンバー登録が完了した時点で数える（途中でやめた人が回数を消費しないように）
  - ログイン画面からは新しいユーザーを作らない。未登録の連絡先には「登録されていません。招待リンクから登録してください」と表示
  - 規約への同意は、バージョンと日時をプロフィールに記録する
- **補足（Claude の判断）**
  - 電話番号は「090-1234-5678」や全角数字でも受け付け、日本の番号（+81）として扱う
  - 初回プロフィールは「表示名（必須）」→「できること・ひとこと（スキップ可）」の2段階。表示名を入れた時点でメンバー登録完了

## 2026-11-09 相談一覧・投稿の実装

### D-18 相談一覧・投稿
- **決定（依頼者）**：相談一覧と投稿を実装する
- **Claude の判断で決めたこと**
  - 投稿後の行き先として、相談詳細（B-03）を簡易版で用意（本文・公開範囲・関係者・議論マップの枠）。スレッド・反応・相談の設定は次の段階
  - 「関係者のみ」で投稿すると招待が届くため、招待を受ける画面（B-09）を参加／辞退だけの簡易版で用意。問い合わせ（B-10）は次の段階
  - 一覧の「すべて」には、管理者閲覧で見られるだけの他人の「関係者のみ」相談は出さない（管理者のホームに他人の非公開の相談が並ばないように。閲覧は管理画面・通報対応から）
  - 「関係者のみ」で投稿するときは、関係者を1人以上選ぶ必要がある
  - 議論マップは AI 処理がまだないため、投稿直後は「材料集め中」のチェックリストを表示する
  - メンバー・DM のタブは「準備中」として薄く表示

## 2026-11-09 議論マップの処理フロー

### D-19 議論マップの処理フロー
- **決定（依頼者）**：議論マップの処理フローを整備する
- **Claude の判断で決めたこと**（詳細は [discussion-map.md](./discussion-map.md)）
  - Supabase の定期処理（pg_cron、1分ごと）から Edge Function を呼び、処理待ちの相談をまとめて処理する
  - 投稿直後・AI をオンにした直後・「今すぐ更新」はすぐ処理、発言は最後の書き込みから3分待ってまとめて処理
  - 参加者の名前は AI に送らず、P1, P2 … のラベルで送る。担当者はラベルで返してもらい DB 側で名前に戻す
  - 「材料がそろったか」は、ゴールと今の状況を AI が判定し、投稿者以外の発言は DB の件数で判定する
  - 承認前の人向けの概要版は、材料がそろったときだけ作り、名前・引用を入れない
  - 既定のモデルは Claude Opus 5.5（effort は medium）。設定で Claude Haiku 5.5 などに変えられる
  - 安全上の理由で断られた場合は、Anthropic 推奨の別モデルで自動的にやり直す
  - 失敗時はそれまでのマップを残し、間隔を広げながら再試行（最大約1時間）。すべての呼び出しを ai_runs に記録
  - 関係者招待の期限切れも同じ定期処理で行う
