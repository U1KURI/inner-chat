# inner-chat 要件定義（v0.5）

> 決定の経緯は [decisions.md](./decisions.md) を参照。

> 知人だけが入れるクローズドなチャット。
> 「誰が何をできるか」を見える化し、ふわっとした相談から会話が始まる場をつくる。

---

## 1. コンセプト

| 項目 | 内容 |
| --- | --- |
| 目的 | 幅広い知人ネットワークの「できること」を可視化し、曖昧な相談・案件を適任者につなぐ |
| 利用者 | 運営者の知人（職種・業界・年齢層がバラバラな人たち） |
| 規模 | **50人未満** |
| 性格 | 招待制・クローズド。**招待は管理者のみ** |
| お金 | **扱わない**（受発注・決済機能はなし。「人をつなぐ」まで） |
| 形態 | **Web（PWA）・レスポンシブ**（スマホ／タブレット／PC） |

### Slack / LINE との差別化
1. **「できること」×「相談」のマッチング**：誰に聞けばいいか分からない状態から会話を始められる
2. **LINE を使いたくない人も参加できる**：メールアドレス（または電話番号）さえあれば使える。アプリのインストールも不要（ブラウザ／PWA）
3. **身内だけの安心感**：管理者の招待制で、知らない人は入ってこない

### 想定する利用シーン
1. Aさん「店のWebサイトをなんとかしたい。何から手をつければいいか分からない」と投稿（公開範囲：全体）
2. AI が相談を要約・タグ付けし、「Web制作」「マーケ」タグを持つメンバーに通知
3. Bさん・Cさんが「話聞けます」と反応 → 相談スレッドで会話開始
4. 込み入った話になったので、Aさんが公開範囲を「関係者のみ（Bさん・Cさん）」に変更
5. Bさんが「デザインはDさんが詳しい」と Dさんを関係者に招待 → Dさんは招待者に質問してから承認 → 参加
6. 具体的な進め方は Aさん ⇔ Bさん の DM で詰める

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| メンバー | 招待されてアカウントを作った人 |
| 管理者 | 招待・メンバー管理ができるメンバー。複数人可 |
| できること | メンバーがプロフィールに掲げるスキル・経験・提供可能なこと |
| 相談 | ふわっとした困りごと・依頼の投稿。ここから会話が始まる |
| 相談スレッド | 相談に紐づくグループ会話 |
| 関係者 | 「関係者のみ」公開の相談を閲覧・発言できるメンバー |
| 関係者招待 | ある人を関係者に加えるための招待。受け取った本人の承認で成立する |
| 議論マップ | 相談ごとに AI が自動生成する「議論の大まかな流れ」と「全体感における現在位置」 |
| DM | メンバー同士の 1対1／少人数のメッセージ |

## 3. 権限

| 操作 | 一般メンバー | 管理者 |
| --- | :---: | :---: |
| 招待リンク（サービスへの招待）の発行 | – | ○ |
| 他メンバーを管理者に格上げ | – | ○ |
| 管理者を一般メンバーに戻す | – | ○（ただし最後の1人は不可） |
| メンバーの停止・退会処理 | – | ○ |
| 通報への対応・タグの整理 | – | ○ |
| プロフィール編集・相談投稿・DM | ○ | ○ |
| 「関係者のみ」相談の閲覧 | 関係者のみ | 「管理者の閲覧を許可」がオンの相談 ＋ 通報された相談 |
| 「関係者のみ」相談への関係者招待 | 投稿者・関係者 | 閲覧できる相談のみ可 |

## 4. 機能要件

### 4.1 アカウント・参加

| # | 要件 |
| --- | --- |
| A-1 | **メールアドレス認証をデフォルト**とする（ワンタイムコード／マジックリンク、パスワード不要） |
| A-2 | **SMS（電話番号）認証は希望者のみ**選べる（メールを使いたくない・使えない人向け） |
| A-3 | **管理者が発行した招待リンク** を持つ人だけ登録できる |
| A-4 | 招待リンクは有効期限・使用回数（基本1回）を設定できる |
| A-5 | 誰がいつ招待したかを記録する |
| A-6 | 後からメール／電話番号を追加・変更できる（両方紐付け可） |
| A-7 | 管理者は他メンバーを **管理者に格上げ／一般に戻す** ことができる |
| A-8 | 管理者はメンバーを停止・退会させられる |
| A-9 | 本人による退会（データ削除方針は 6章） |
| A-10 | 登録時に利用規約・プライバシーの案内に同意する（AI 利用の告知を含む。4.8 参照） |

### 4.2 プロフィール「できること」

| # | 要件 |
| --- | --- |
| P-1 | 表示名・アイコン・ひとこと自己紹介 |
| P-2 | **できること** をタグ＋自由記述で登録（例: `Web制作` `税務相談` `動画編集` `子育て相談`） |
| P-3 | タグは既存候補から選択＋新規追加可（表記ゆれ対策） |
| P-4 | 各「できること」に 経験レベル／実績例 を任意で付記 |
| P-5 | 「相談受付中 / ちょっと忙しい / 休止中」のステータス |
| P-6 | 「できること」でメンバー検索・カタログ表示 |
| P-7 | 「興味あり・勉強中」など "できる" 未満も書ける欄 |

### 4.3 相談（ふわっと案件）

| # | 要件 |
| --- | --- |
| C-1 | タイトル＋本文だけで気軽に投稿できる（タグ・カテゴリは任意） |
| C-2 | 相談一覧（タイムライン）。自分が閲覧可能なものだけ表示 |
| C-3 | 「話聞けます」「詳しい人知ってます」などワンタップ反応 |
| C-4 | 相談ごとのスレッドで会話できる |
| C-5 | スレッドから特定の人との DM に移行できる |
| C-6 | 相談内容と「できること」タグを照合し、合いそうな人へ通知／おすすめ表示 |
| C-7 | AI で相談文を要約・タグ付けし、マッチング精度を上げる（投稿者が確認・修正可） |
| C-8 | ステータス管理（募集中 / 進行中 / 解決 / クローズ） |
| C-9 | 「この人に聞いてみて」と他メンバーを紹介（メンション）できる |

### 4.4 公開範囲

| # | 要件 |
| --- | --- |
| V-1 | 相談の投稿時に公開範囲を選べる：**全体に公開** / **関係者のみ** |
| V-2 | 「関係者のみ」の場合、投稿者が最初の関係者を選ぶ（メンバー一覧・タグ検索から）。選ばれた人には関係者招待が届く（4.5） |
| V-3 | **途中から公開範囲を変更できる**（全体 ⇄ 関係者のみ）。変更できるのは投稿者のみ |
| V-4 | 全体 → 関係者のみ に絞るとき、それまでにスレッドで発言・反応した人を候補として提示。投稿者が選んだ人は**承認不要でそのまま関係者**になる（すでに会話に参加しているため） |
| V-5 | 関係者から外れた人は、以後その相談・スレッドを閲覧できない（一覧からも消える）。関係者を外せるのは投稿者のみ。本人はいつでも自分から抜けられる |
| V-6 | 関係者のみ → 全体 に広げるとき、確認ダイアログを出す（過去のやりとりも全員に見える旨） |
| V-7 | 公開範囲・関係者の変更はスレッド内にシステムメッセージで記録する（「○○さんが公開範囲を変更しました」「△△さんが参加しました」） |
| V-8 | 「関係者のみ」の相談は AI マッチング通知の対象外（関係者以外に内容が漏れないように） |

#### 管理者の閲覧許可

| # | 要件 |
| --- | --- |
| V-9 | 「関係者のみ」を選ぶと **「管理者の閲覧を許可する」チェックボックス** を表示。**デフォルトはオン** |
| V-10 | チェックボックスの横に説明文を表示：**「調整や仲裁が必要になった場合に備えて、管理者が内容を確認できるようにします」** |
| V-11 | 投稿者は後からオン／オフを変更できる（変更はスレッドにシステムメッセージで記録） |
| V-12 | オフの場合でも、関係者から**通報された相談**は管理者が閲覧できる |
| V-13 | 関係者は、その相談で管理者閲覧がオン／オフのどちらかを確認できる（相談ヘッダーに表示） |

### 4.5 関係者招待（承認プロセス）

| # | 要件 |
| --- | --- |
| I-1 | 「関係者のみ」の相談に関係者を招待できるのは **投稿者・関係者・管理者**（管理者は閲覧を許可された相談のみ） |
| I-2 | 招待時に、招待者はひとことメッセージを添えられる（「デザインの件でDさんの意見が欲しいです」など） |
| I-3 | 招待を受けた人が **承認すると関係者に加わる**。辞退もできる |
| I-4 | **承認前に見えるのは** 相談タイトル・投稿者・招待者・招待メッセージ・現在の関係者一覧・**議論マップ（4.10）** のみ（本文やスレッドの発言そのものは承認後に閲覧可） |
| I-5 | **承認前に問い合わせできる**：招待画面から「質問する」で、招待者（必要なら投稿者）とやりとりできる。このやりとりは招待に紐づく専用の会話として残る |
| I-6 | 投稿者以外が招待した場合、投稿者に通知する。投稿者は承認前の招待を取り消せる |
| I-7 | 招待には有効期限を設ける（例：14日）。期限切れ・辞退は招待者に通知 |
| I-8 | 承認待ち・辞退・承認済みの状況を、招待者と投稿者が確認できる |

### 4.6 個別メッセージ（DM）

| # | 要件 |
| --- | --- |
| D-1 | メンバー同士で 1対1 メッセージ |
| D-2 | 少人数グループ DM |
| D-3 | テキスト・画像・ファイル添付 |
| D-4 | 既読表示 |
| D-5 | ブロック・ミュート |

### 4.7 通知

| # | 要件 |
| --- | --- |
| N-1 | DM・自分の相談への反応・メンション・**関係者招待（受信・承認・辞退・問い合わせ）** を通知 |
| N-2 | 通知手段：アプリ内 / メール / Web プッシュ（PWA） |
| N-3 | 通知の受信設定（タグ一致の新着相談、メール頻度など） |

### 4.8 AI 利用の告知

| # | 要件 |
| --- | --- |
| AI-1 | 利用規約・案内に「相談本文とスレッドを、要約・タグ付け・議論マップ生成のため外部 AI サービス（Anthropic の Claude）に送信する」旨を明記。**「関係者のみ」の相談も議論マップ生成のため送信対象**になることを明記 |
| AI-2 | 相談の投稿画面にも短い注記を表示（「相談内容は AI が要約し、議論の流れを整理します」） |
| AI-3 | DM は AI に送らない |
| AI-4 | 送信先 AI サービスが入力データを学習に使わないことを案内に記載 |
| AI-5 | 「関係者のみ」の相談は、AI に送っても **マッチング通知・おすすめには使わない**（V-8） |
| AI-6 | **相談ごとに「AI を使う」をオフにできる**（投稿時に選択。デフォルトはオン）。変更できるのは投稿者のみ。途中でオン／オフを切り替え可 |
| AI-7 | オフの相談は、要約・タグ付け・議論マップ生成のいずれにも AI に送らない。AI によるマッチング通知も行わない（タグは投稿者が手動で付けられ、手動タグによるマッチングは行う） |
| AI-8 | オフの間、議論マップ欄には「この相談は AI を使わない設定です」と表示し、投稿者・関係者が手入力で埋められる |
| AI-9 | 途中でオフにした場合、それ以降は AI に送らない。生成済みの議論マップは残す（投稿者が削除可）。オフ→オンに戻すと、その時点の内容で生成し直す |
| AI-10 | AI のオン／オフ変更はスレッドにシステムメッセージで記録し、相談ヘッダーに状態を表示する |

### 4.10 議論マップ（議論の流れと現在位置）

全ての相談で自動生成し、相談画面の上部と、関係者招待の承認前画面に表示する。

#### 表示内容

| 項目 | 内容 |
| --- | --- |
| ゴール | この相談で最終的に何をしたいか（1〜2行） |
| 議論の大まかな流れ | これまでの経緯をフェーズ単位で3〜6項目程度に要約（例：「課題の共有 → 選択肢の洗い出し → 予算の確認」） |
| 全体感における現在位置 | 標準フェーズ上のどこにいるかを表示：**① 課題整理 → ② 情報・選択肢集め → ③ 検討・比較 → ④ 決定 → ⑤ 実行・フォロー** |
| 決まったこと | 合意済みの事項 |
| 未決の論点 | まだ決まっていないこと |
| 次の一歩 | 次に誰が何をするとよさそうか |
| 更新日時 | いつ時点の要約か |

#### 要件

| # | 要件 |
| --- | --- |
| MAP-1 | **全ての相談で AI が自動生成**する（全体公開・関係者のみ とも）。ただし AI 利用をオフにした相談は除く（AI-6〜9） |
| MAP-2 | **最低限の材料が揃うまでは枠だけ表示**し、「このような項目があれば、議論の流れや全体感と現在位置を出せます」と案内する。不足項目をチェックリストで表示（例：☐ 何をしたいか（ゴール） ☐ 今の状況 ☐ 期限や予算などの条件 ☐ 2人以上のやりとり） |
| MAP-3 | 最低限の材料（目安）：**ゴールと現状が本文から読み取れる** かつ **投稿者以外の発言が1件以上**。判定は AI が行い、不足項目を返す |
| MAP-4 | スレッドに新しい発言があると自動更新する（連続投稿時はまとめて更新：例 最後の発言から数分後、または一定件数ごと） |
| MAP-5 | 手動の「今すぐ更新」ボタン |
| MAP-6 | 投稿者・関係者は内容を修正できる（AI の誤解を訂正）。手修正した項目は次回の自動更新で上書きしない |
| MAP-7 | **承認前の招待者に見せる版**では、個人名を伏せ発言の引用をしない「概要版」を表示する（本文・発言そのものは承認後） |
| MAP-8 | 過去の版を残し、流れの変化を振り返れる |
| MAP-9 | 公開範囲の変更・関係者の参加もフェーズ上の出来事として反映できる |

## 5. コストの見込み

### 5.1 認証

**メール認証は 50人規模なら無料で運用できる見込み。**

| 項目 | 内容 | 費用 |
| --- | --- | --- |
| 認証基盤（Supabase Auth） | メールでのワンタイムコード／マジックリンクは無料プランに含まれる | 0円 |
| メール送信（SMTP） | Supabase 標準のメール送信は送信数が厳しく制限され本番向きではないため、外部の送信サービスを接続する。Resend・Brevo などの無料枠（月数千通・1日数百通程度）で 50人規模なら十分 | 0円 |
| 独自ドメイン | 送信元の信頼性（迷惑メール判定回避）のため推奨 | 年 1,000〜2,000円程度（すでに持っていれば 0円） |
| SMS（希望者のみ） | Twilio 等の従量課金。1通あたり十数円前後 | 希望者数 × ログイン回数ぶん。数人なら月数百円以下 |

※ 各サービスの無料枠・料金は変わるため、実装着手時に最新の料金を確認する。
※ 一度ログインすればしばらくセッションが続くため、認証メール／SMS の送信回数は少ない。

---

### 5.2 AI 利用

前提（50人未満）：相談 月100件、議論マップの更新 1件あたり平均10回 → 月1,000回程度の AI 呼び出し、1回あたり入力 5,000 / 出力 1,000 トークン程度。

| モデル | 料金（入力 / 出力 100万トークンあたり） | 月額の目安 |
| --- | --- | --- |
| Claude Opus 5.5（最上位・既定の推奨） | $4 / $20 | 数千円程度（〜$40 前後＋思考トークン分） |
| Claude Haiku 5.5（軽量・低価格） | $0.10 / $0.50 | 数百円以下（〜$1 程度） |

※ どのモデルを使うかは運用者が決める。タグ付けだけ軽量モデル、議論マップは上位モデル、のような使い分けも可能。
※ 料金は 2026年10月時点の情報。着手時に最新の料金を確認する。

## 6. 非機能要件

| 分類 | 内容 |
| --- | --- |
| 規模 | 50人未満。同時接続も少数のため、マネージドサービスの無料〜低価格枠で運用可能 |
| 端末 | **レスポンシブ Web + PWA**（ホーム画面追加・Web プッシュ）。スマホ最優先、PC でも快適に |
| 使いやすさ | IT に不慣れな人・LINE を使わない人でも使える：パスワード不要、操作は最小限、文字サイズ配慮 |
| プライバシー | メール・電話番号は他メンバーに非公開。「関係者のみ」の相談・管理者閲覧可否・承認前の閲覧制限は、サーバー側（DB の行レベル権限）で制御する |
| セキュリティ | 招待リンクの推測困難化、OTP の試行回数制限、HTTPS |
| リアルタイム性 | DM・スレッドはリアルタイム反映 |
| データ | 退会時：プロフィールは削除、過去の発言は「退会したメンバー」表示で残す |

## 7. 技術スタック（推奨）

**Next.js + Supabase**

- Auth：メール OTP（デフォルト）・電話 OTP（希望者）
- メール送信：Resend などの外部 SMTP（無料枠）
- Postgres：タグ検索・マッチング、**行レベルセキュリティ（RLS）で公開範囲・管理者閲覧可否を確実に制御**
- Realtime：スレッド・DM のリアルタイム反映
- Storage：画像・ファイル添付
- PWA：Next.js + Service Worker（Web Push）
- AI（要約・タグ付け・議論マップ生成）：Claude API（Anthropic）

## 8. 実装の順番（案）

全機能を対象としつつ、以下の順で作る。

1. 招待リンク・メール認証・管理者権限（SMS 認証は後追い）
2. プロフィール「できること」・メンバー検索
3. 相談投稿・スレッド・反応・**公開範囲（全体／関係者のみ・途中変更・管理者閲覧許可）**
4. **関係者招待と承認プロセス（問い合わせ含む）**
5. DM（1対1 → グループ、添付、既読）
6. 通知（アプリ内 → メール → Web プッシュ）
7. **議論マップ**・タグ照合マッチング → AI 要約・タグ付け
8. 通報・タグ整理などの管理機能、SMS 認証
