# inner-chat 要件整理（ドラフト v0.1）

> 知人だけが入れるクローズドなチャット。
> 「誰が何をできるか」を見える化し、ふわっとした相談から会話が始まる場をつくる。

---

## 1. コンセプト

| 項目 | 内容 |
| --- | --- |
| 目的 | 幅広い知人ネットワークの「できること」を可視化し、曖昧な相談・案件を適任者につなぐ |
| 利用者 | 運営者の知人（職種・業界・年齢層がバラバラな人たち） |
| 性格 | 招待制・クローズド。公開SNSではない |
| 一言で | 「知り合いの知り合いに気軽に相談できる、身内版の掲示板＋チャット」 |

### 想定する利用シーン
1. Aさん「店のWebサイトをなんとかしたい。何から手をつければいいか分からない」と投稿
2. プロフィールに「Web制作」「デザイン」「マーケ」と書いている人に通知・おすすめ表示
3. Bさん・Cさんが「話聞けます」と反応 → 案件スレッドで会話開始
4. 具体的な話は Aさん ⇔ Bさん の個別メッセージ（DM）で進める

---

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| メンバー | 招待されてアカウントを作った人 |
| できること | メンバーがプロフィールに掲げるスキル・経験・提供可能なこと |
| 相談（案件） | ふわっとした困りごと・依頼の投稿。ここから会話が始まる |
| 相談スレッド | 相談に紐づくグループ会話 |
| DM | メンバー同士の 1対1 メッセージ |

---

## 3. 機能要件

優先度: **MVP** = 最初のリリースに必須 / **次** = 早めに追加 / **将来** = 余裕があれば

### 3.1 アカウント・参加（招待制）

| # | 要件 | 優先度 |
| --- | --- | --- |
| A-1 | **電話番号 または メールアドレス** でアカウント作成できる | MVP |
| A-2 | パスワードレス認証（SMS / メールにワンタイムコード送信） | MVP |
| A-3 | **招待制**：招待リンク（またはコード）を持つ人だけ登録できる | MVP |
| A-4 | 招待リンクは有効期限・使用回数を設定できる | MVP |
| A-5 | 誰が誰を招待したかを記録する（信頼の連鎖・トラブル時の追跡用） | MVP |
| A-6 | 後から電話番号／メールを追加・変更できる（両方紐付け可） | 次 |
| A-7 | 管理者がメンバーを停止・退会させられる | MVP |
| A-8 | 招待できる人を制限（管理者のみ / 全員 / 一定条件）できる | 次 |
| A-9 | 新規登録に管理者承認を挟むモード | 将来 |

### 3.2 プロフィール「できること」

| # | 要件 | 優先度 |
| --- | --- | --- |
| P-1 | 表示名・アイコン・ひとこと自己紹介 | MVP |
| P-2 | **できること** をタグ＋自由記述で登録（例: `Web制作` `税務相談` `動画編集` `子育て相談`） | MVP |
| P-3 | タグは既存候補から選択＋新規追加可（表記ゆれ対策） | MVP |
| P-4 | 各「できること」に 経験レベル／実績例／有償・無償・応相談 を任意で付記 | 次 |
| P-5 | 「いま相談受付中 / 忙しい」などのステータス | 次 |
| P-6 | 「できること」でメンバー検索・一覧（カタログ表示） | MVP |
| P-7 | 「興味はある・勉強中」など、"できる"未満も書ける欄 | 将来 |

### 3.3 相談（ふわっと案件）→ 会話の起点

| # | 要件 | 優先度 |
| --- | --- | --- |
| C-1 | タイトル＋本文だけで気軽に相談を投稿できる（カテゴリ不要でもOK） | MVP |
| C-2 | 相談一覧（タイムライン）を全メンバーが見られる | MVP |
| C-3 | 「話聞けます」「詳しい人知ってます」などワンタップ反応 | MVP |
| C-4 | 相談ごとにスレッドで会話できる | MVP |
| C-5 | 相談者がスレッドから特定の人と DM に移行できる | MVP |
| C-6 | 相談内容と「できること」タグを照合し、合いそうな人に通知／おすすめ表示 | 次 |
| C-7 | AI で曖昧な相談文を要約・タグ付けし、マッチング精度を上げる | 将来 |
| C-8 | ステータス管理（募集中 / 進行中 / 解決） | 次 |
| C-9 | 公開範囲の指定（全員 / 指定メンバーのみ） | 将来 |
| C-10 | 「この人に聞いてみて」と他メンバーを紹介（メンション）できる | 次 |

### 3.4 個別メッセージ（DM）

| # | 要件 | 優先度 |
| --- | --- | --- |
| D-1 | メンバー同士で 1対1 メッセージ | MVP |
| D-2 | テキスト・画像・ファイル添付 | MVP（ファイルは次でも可） |
| D-3 | 既読表示 | 次 |
| D-4 | 少人数グループ DM | 次 |
| D-5 | ブロック・ミュート | MVP |

### 3.5 通知

| # | 要件 | 優先度 |
| --- | --- | --- |
| N-1 | DM・自分の相談への反応・メンションを通知 | MVP |
| N-2 | 通知手段：アプリ内／メール／プッシュ（PWA または ネイティブ） | MVP はアプリ内＋メール |
| N-3 | 通知の受信設定（タグ一致の新着相談を受け取る／受け取らない等） | 次 |

### 3.6 管理

| # | 要件 | 優先度 |
| --- | --- | --- |
| M-1 | メンバー一覧・招待履歴の閲覧 | MVP |
| M-2 | 通報機能と対応フロー | 次 |
| M-3 | タグの統合・整理（表記ゆれ解消） | 次 |

## 4. 非機能要件

| 分類 | 内容 |
| --- | --- |
| 規模 | 当面 数十〜数百人 を想定（要確認） |
| プライバシー | 電話番号・メールは他メンバーに非公開（本人が公開を選んだ場合のみ表示） |
| セキュリティ | 招待リンクの推測困難化、OTPの試行回数制限、通信の暗号化（HTTPS） |
| 端末 | スマホ中心（まず PWA / レスポンシブ Web）、PC でも利用可 |
| 幅広い利用者への配慮 | ITに不慣れな人でも使える導線：パスワード不要、操作は最小限、文字サイズ配慮 |
| リアルタイム性 | DM・スレッドはリアルタイム反映 |
| コスト | SMS 送信は従量課金。メール認証を基本にして SMS は選択式にする案も |
| データ | 退会時のデータ削除方針を定める |

## 5. 決めておきたいこと（未決事項）

1. **規模感**：最初は何人くらい？ 将来どこまで増やす想定か
2. **招待の権限**：誰でも招待できる？ 管理者だけ？（広がりと信頼のトレードオフ）
3. **相談の公開範囲**：全員に見える前提でよいか。センシティブな相談はどう扱うか
4. **お金の扱い**：有償の仕事の受発注まで想定するか、「つなぐ」までに留めるか
   （決済を入れると要件・法的対応が一気に増えるため、最初は「つなぐ」まで推奨）
5. **形態**：Web（PWA）で始めるか、最初からスマホアプリか（Web 推奨：配布・審査が不要）
6. **既存ツールとの比較**：Slack / Discord / LINE オープンチャット + スプレッドシートで代替できないか、
   独自開発の価値は「できること × 相談マッチング」にある、という整理でよいか
7. **AIマッチング**：どの段階で入れるか
8. **運営者**：管理者は1人か複数か

---

## 6. MVP スコープ案

最小限でまず回すなら：

- 招待リンク ＋ メール／電話番号のワンタイムコード登録
- プロフィール（できることタグ＋自由記述）とメンバー検索
- 相談の投稿・一覧・スレッド・「話聞けます」反応
- DM（テキスト・画像）
- アプリ内＋メール通知
- 管理者によるメンバー停止

## 7. 技術スタック候補（参考・未決定）

| 案 | 構成 | 向いているケース |
| --- | --- | --- |
| A | Next.js + Supabase（Auth: メールOTP / 電話OTP、Realtime、Postgres） | 少人数で早く作りたい。認証・リアルタイムを丸ごと任せられる |
| B | Next.js + Firebase（Auth: 電話・メールリンク、Firestore） | Google 系に寄せたい、プッシュ通知も楽にしたい |
| C | 自前バックエンド（Node/Go + Postgres + WebSocket）＋ Twilio 等 | 細かく制御したい、将来大規模化 |

現時点の推奨は **案A**（電話番号・メール両方のOTPに標準対応、Postgres でタグ検索・マッチングを組みやすい）。
